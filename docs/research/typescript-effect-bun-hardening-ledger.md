# Effect v3 and Bun hardening ledger

This ledger records the concerns evaluated against standards commit
`215ffabfa4cc97e8cd86db5d9f86a7a4c90fb476` and Starbabe commit
`c61d5ac6d0b1f7e73379b0170b42b72033768e84`. The installed versions are
Effect 3.22.1, `@effect/platform` 0.97.1, `@effect/platform-bun` 0.91.0,
`@effect/language-service` 0.87.1, TypeScript 6.0.3, and Bun 1.3.14.

Claim labels have these meanings:

- **VERIFIED FACT**: established by the pinned declarations or source, repository
  source, or an official version-matched contract.
- **EMPIRICAL RESULT**: observed in a deterministic local probe or executed gate.
- **REASONED INFERENCE**: a conclusion drawn from verified facts or results.
- **PROJECT PREFERENCE**: a deliberate standards choice rather than an Effect law.

## H-001: Validate duration input before normalization

| Field          | Content                                                                                                                                                                                                                                                                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Location       | `TS/src/endpoint-checker.ts`: `CheckPolicy` accepts `Duration.DurationInput`; `validateDuration` calls `Duration.decodeUnknown` before checking the result.                                                                                                                                                                                 |
| Classification | Correctness                                                                                                                                                                                                                                                                                                                                 |
| Severity       | P0                                                                                                                                                                                                                                                                                                                                          |
| Failure mode   | Negative numbers, negative strings, `NaN`, and negative infinity normalize to zero; positive infinity normalizes to infinity. Validation can therefore erase the distinction that should make the original configuration invalid.                                                                                                           |
| Evidence       | **VERIFIED FACT**: pinned `effect/src/Duration.ts` `decode` delegates numeric inputs to `millis`, while `make` maps `NaN` and values `<= 0` to zero and non-finite positive values to infinity. **EMPIRICAL RESULT**: the baseline fixture accepted negative attempt and retry inputs whenever the normalized zero met the later predicate. |
| General lesson | Validate an external representation before a lossy constructor when the rejected distinction matters. Keep unchecked configuration separate from the normalized domain model.                                                                                                                                                               |
| Proposed patch | Decode finite bounded integer milliseconds and normalized origin strings into `CheckPolicyInput`, then construct an internal `CheckedPolicy` containing only `Duration.Duration`, normalized origins, and bounded integers.                                                                                                                 |
| Enforcement    | Schema/unit tests; semantic test proving invalid policy does not invoke the adapter.                                                                                                                                                                                                                                                        |
| Migration cost | Low: callers replace general `DurationInput` values with explicit millisecond fields.                                                                                                                                                                                                                                                       |
| Disposition    | Fix                                                                                                                                                                                                                                                                                                                                         |
